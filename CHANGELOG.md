# Changelog

## 3.7.0 — 2026-09-13

### Исправлено — тёмный туман теперь реально работает
- **Инверт внутри VFX_FogGroup был подключён по индексу сокетов, а не по имени.** У композиторной ноды Invert порядок сокетов `[Factor, Color]`: карта плотности попадала в **Factor** (степень инверсии), а вход Color оставался чёрным — на выходе инверта была константа 1, и микс при любой глубине показывал слои без тумана. Тёмный/приглушённый туман через рампу при этом не получался вообще. Теперь: плотность → `Color`, `Fac = 1.0`, выход инверта → Mix.Factor — честная формула `factor = 1 − density`.
- **Миграция**: у группы появился маркер версии `vfx_fog_version` (текущая схема = 2). Группы, собранные 3.6.0 (со сломанным инвертом), при первой сборке пересоздаются автоматически; правки рампы в группах новой схемы сохраняются.
- Панель FOG: подсказка «Dark fog: pull ramp black stop up / raise its color» — как сделать тёмный туман.

## 3.6.0 — 2026-09-12

### Новое — туман по референс-схеме (слои собираются ДО фог-группы)
- **Слои собираются в единый стек снаружи**, до входа в туман: фон → shadow-проходы → объектные проходы (с грейдами), цепочка AlphaOver. В фог-группу подаётся одна готовая картинка.
- **VFX_FogGroup переписан на минимальную референс-схему**:
  - Depth (метры) → **ColorRamp (редактируемая)** → Multiply(Strength) → Multiply(Extra Mask) → **Invert** → Mix.Factor;
  - Mix.**A = Fog Color**, Mix.**B = собранные слои** (как на референс-скриншоте: factor 0 = сплошной цвет тумана, factor 1 = чистые слои);
  - MapRange перед рампой клампит сам себя — делений нет, множитель физически не может застрять на 0/1;
  - рампа по умолчанию: чёрный = близко/чисто, белый = далеко/плотный туман; форму кривой правят прямо в ноде `FOG MAP RAMP` внутри группы.
- **Ноды группы собираются один раз** — правки рампы пользователем больше не затираются при каждом чеке ползунка (раньше группа перестраивалась целиком на каждый rebuild). Пересоздание только если группа старой схемы.
- Фолбек глубины: если Z-пас недоступен, метры синтезируются из mist-паса (Z = Mist Start + mist × Mist Depth) нодой `VFX_FOG_DEPTH_FB` — работает в любом случае.
- **Исправлено**: обращение к несуществующей функции `_layer_factor_safe` внутри билдера группы (NameError при каждой сборке тумана, тихо глоталось try/except — туман не собирался вообще).
- Удалены устаревшие per-layer туманные настройки (Fog x(layer), Fog Map Bias/Gain, BG Fog): карта тумана теперь одна общая, per-layer регулировка не нужна. Секция FX → FOG в карточке слоя сообщает, что туман глобальный.

## 3.5.0 — 2026-09-11

### Новое — туман переписан на глубину (Z)
- Основа тумана теперь **Z-глубина в метрах** (Z-пас FOGMAP-сцены), а не mist-маска. Схема без единого деления: MapRange клампит результат сам по себе — множитель физически не может «застрять» на 0 или 1 (причина всех недавних багов).
  - **ближе Fog Start** — тумана нет вообще;
  - **дальше Fog Full** — сплошной цвет тумана;
  - между ними — плавный smoothstep-переход.
- Накладывается **заданный цвет тумана** через Mix по этой карте (белое на карте = плотный туман, тёмное = прозрачный), а не серая маска. Соблюдаются альфа слоёв — силуэты остаются силуэтами.
- **Подстройка карты на слое** (FX → FOG): *Fog Map Bias* — сдвиг слоя по общей карте (плюс = дальше/туманнее, минус = ближе/чище), *Fog Map Gain* — контраст карты на слое (>1 — туман нарастает резче с дистанцией, <1 — мягче/равномернее). Математически: `fac = (MapRange(Z)^Gain − Bias) × Fog x(layer)`, кламп 0..1.
- Фолбэк: если Z-пас недоступен, глубина синтезируется из mist-паса (`Z = Mist Start + mist × Mist Depth`) — схема работает в любом случае.
- В консоли при сборке: `[VFX fog] depth ramp: clear up to X m, full fog at Y m`.
- Остаточные значения старой системы (Fog Full ≤ 1.0) автоматически конвертируются в метры при первой сборке.

## 3.4.2 — 2026-09-11

### Исправлено
- **Туман работал как маска/заливал слой серым** при значении «Fog Full» меньше Mist Start (например, остаточное 0.11–0.59 м): конвертация метров в долю mist делалась нодами внутри группы, и вырожденный диапазон (Full ≤ Start) давал ноль или минус в делении — множитель застревал на 1 (весь слой = сплошной цвет тумана, серые силуэты) или на 0 (туман исчезает). Конвертация перенесена из нодов в Python: при каждой сборке значения **валидруются и лечатся** до того, как попадут в ноды (остаточные доли 0..1 конвертируются в метры, Full < Start поднимается, диапазон clamp'ится в окно mist). В консоль печатается строка `[VFX fog] ramp: X..Y m -> mist A..B (window ...)` — по ней сразу видно, куда лягет туман.

### Изменено
- В секции FOG ползунки «Fog Start / Fog Full» подняты наверх, под ними подпись **depth window: N ... M m** — видны границы окна глубины (Mist Start ... Mist Start+Depth), в метрах которого и нужно задавать туман.

## 3.4.1 — 2026-09-11

### Исправлено
- **Туман полностью исчезал после обновления до 3.4.0**: старое значение «Fog Full» (0.11 — доля mist из старой системы) не мигрировало в метры и оставалось 0.11 м — меньше, чем Mist Start (≈2.2 м). Диапазон рампы вырождался, множитель глубины обнулялся, туман пропадал целиком. Причины и лечение:
  - миграция в `register()` молча обрывалась на первой же сцене с ошибкой записи — теперь она идёт **по-сценно** (одна проблемная сцена не блокирует остальные) и печатает в консоль, что перенесла;
  - страховка на месте: при каждой сборке композа вырожденная рампа (Fog Full ≤ Fog Start) **лечится автоматически** — Fog Full поднимается до разумной дистанции (Mist Start + половина Mist Depth), в консоль печатается `VFX: healed degenerate fog ramp`. Туман больше не может пропасть из-за кривых значений.

## 3.4.0 — 2026-09-11

### Исправлено

## 3.3.1 — 2026-09-11

### Исправлено
- **Объект, привязанный к родительской пустышке (Empty), в слое-сцене сбивался по позиции и размеру** — в сцену слоя линковались только сами объекты, без родительских Empty, и депсграф считал ребёнка без трансформа родителя (потерялись и позиция, и масштаб). Теперь:
  - `ensure_parent_empties()` автоматически линкует цепочку родительских Empty в коллекцию слоя (при создании слоя и при Add Selected);

  - holdout-прокси теперь **родительятся на ту же пустышку** (живая привязка, следует за анимацией Empty), а не запекают матрицу один раз;
  - повторное использование прокси обновляет трансформ (раньше прокси оставался на старом месте после перемещения объекта).

## 3.3.0 — 2026-09-11

### Новое
- **Система взаимной окклюзии слоёв (holdout)**: объект, пересекающий объект другого слоя (частью спереди, частью сзади), теперь склеивается корректно. Для каждого слоя создаётся коллекция `VFX_<id>_OCCL` с holdout-прокси объектов всех ДРУГИХ слоёв: прокси рендерятся дыркой (alpha=0) и по глубине вырезают всё позади себя прямо в рендере слоя. Режимы на слой:
  - **AUTO** (по умолчанию) — все остальные слои окклюдируют, ничего настраивать не надо;
  - **MANUAL** — список слоёв-окклюдеров с чекбоксами (точечно исключить ненужный);
  - **OFF** — окклюзия выключена.
- **Holdout-прокси не влияют на свет**: visible_shadow/diffuse/glossy/transmission/volume_scatter = False, только камера. Не попадают в FOGMAP (туман/грейд их не видят), не рендерятся как видимая геометрия, слой никогда не окклюдирует сам себя.
- **Прокси переиспользуются по имени** (`<Object>_VFXHoldout`): Refresh/Rebuild не плодят дубли, лишние удаляются, сменённый меш подхватывается.
- **Порядок склейки (composite sort)**: глобально `AUTO` (слои сортируются по расстоянию до камеры — ближний объект слоя = слой поверх) или `MANUAL` (порядок списка, меняется drag'ом). BACKGROUND всегда самый нижний. Порядок печатается в консоль при сборке (`[VFX order]`) и отображается в панели «COMPOSITING ORDER» с расстояниями.
- **UI**: в карточке слоя секция OCCLUSION (раскрывающаяся): режим, список окклюдеров, число прокси, кнопка Refresh. Глобально — «COMPOSITING ORDER» в настройках рендера.
- **Автоматика**: окклюзия пересчитывается при создании/удалении слоя, добавлении/удалении объектов и перед каждым рендером (встроено в Render All Layers и Refresh Proxies). Кнопка «Refresh Occlusion» — для точкиечной пересборки активного слоя.
- **Самопроверка**: после сборки и Refresh печатает по каждому слою список окклюдеров, число прокси и сколько из них помечены holdout, проверяет линк коллекции в сцену слоя, что ни один слой не окклюдирует сам себя, что фон всегда первый; печатает итоговый порядок склейки; предупреждает, если слой рендерится не в Cycles (в EEVEE Next holdout зависит от версии Blender).

### Изменено
- Слой как единое целое в цепочке склейки: shadow-под проходит под объектным проходом того же слоя (было: порядок зависил от направления обхода).
- `vfx.refresh_proxies` теперь обновляет и shadow-, и occlusion-прокси.

## 3.2.1 — 2026-09-11

### Исправлено
- **Настоящая причина «Panel draw error: no attribute 'fog_expanded'»**: все масочные энумы (`grade_mask_source`, `fog_mask_source`, `glare_mask_source`, `dof_mask_source` и т.д.) объявлялись с динамическим `items=функция` и строковым `default='NONE'`. Такая комбинация запрещена в RNA Blender (`'default' can only be an integer when 'items' is a function`), класс регистрировался **частично** — без этих свойств, отсюда и падение панелей. Энумы переведены на статический кортеж `_MASK_SOURCE_ITEMS`.
- `unregister()` теперь дополнительно вычищает осиротевшие `VFX_*` классы из `bpy.types` (последствия частичной регистрации: «already registered as a subclass» при повторной загрузке).

## 3.2.0 — 2026-09-11

### Исправлено
- **Panel draw error: 'VFXProject' object has no attribute 'fog_expanded'** — причина: после переноса/переименования папки аддона в Blender оставалась устаревшая (stale) RNA-регистрация класса `VFXProject` из старой копии, и новая UI рисовала по старым свойствам. Теперь `register()`:

- Панели теперь не падают целиком, если `Scene.vfx` не зарегистрирован: показывают понятное сообщение «restart Blender» вместо `Panel draw error`.

## 3.1.0 — 2026-09-10

### Новое
- **Система масок** (по ТЗ): у DOF, GLARE, MASTER GRADE и FOG появилась секция MASK — источники **Ext node / Alpha / Depth / Luma**, инверсия, мягкость краёв (px). Эффект не переделывается, а оборачивается по схеме `Mix(fac=MASK, A=original, B=effect)`. Все масочные ноды `MASK_*` переиспользуются по имени.
- **Per-layer грейды с масками**: грейд каждого слоя (VFX_Grade, exposure/temp/lift/gain/sat/contrast) по умолчанию ограничен альфой слоя (силуэт), либо маской Ext/Depth/Luma.
- **Пипетка Cryptomatte** (`vfx.pick_cryptomatte`): клик по объекту в 3D-виде — его имя пишется в Cryptomatte-ноду `VFX_CRYPTO_PICK`, которая подключается как Ext-маска к грейду слоя или мастер-грейду.
- **Master Grade с маской**: финальный грейд всей картинки с секцией MASK и Preview.
- **Preview Mask** в каждой MASK-секции: показывает маску эффекта во viewer.
- **Самопроверка после сборки**: печатает в консоль состояние всех масочных цепочек и висячие MASK-ноды.

- **DOF (Camera Focus) переделан**: глубина (метры) -> редактируемая ColorRamp в ноде `DOF FOCUS RAMP` -> variable-size blur. Рампа правится прямо в node editor.
- Выключение эффекта теперь удаляет его ноды из компа, а не просто перестраивает связи.

### Исправлено
- **Color Match** не работал: синтаксическая ошибка + ноды Blender 5.2 — переписан с фолбэками.
- **Lens Distortion**: параметры панели теперь синхронизированы с нодой (по точным именам сокетов).

### Удалено
- **Atmospheric Blur** — заменён DOF с рампой.
- Старая Cryptomatte-фича (файл cryptomatte.py) — вместо неё пипетка + EXT-маски.
